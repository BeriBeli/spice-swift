## 动画流畅度与一致性

同一页播放75s，固定分析宿主V派发后的15→60s，分母45s。源canvas为192×108放大到客体全屏；每行4组magic/ID/CRC，共432区域。八个指针保留区仍记录，完整判据要求其余424区域全部合法且同ID。这是采样到的码区域一致性，不是任意自然视频逐像素完整FPS。

| 指标 | Maspice | CocoaSpice TLS变体 |
| --- | ---: | --- |
| 源端实际绘制率，完整75s | 30.304/s | 30.305/s |
| 观测一致码更新 | 372个 / 45s = **8.27/s** | 无可用于完整FPS排名的结果 |
| 区域ID更新率中位数 | 12.56/s | 仅最右1/4约29.96/s可校验 |
| 混合码状态时间占比 | 75.09% | 动态码失读，不可比较 |
| 未能判同/判异的时间占比 | 6.71% | 正式窗100% |
| 无新一致ID的间隔p95 / max | 251 / 927ms | 不发布比较值 |
| >100ms / >250ms一致进展间隔，含边界 | 159 / 19 | 不发布比较值 |

一致进展长间隔不是“所有像素冻结”：混合/未知期间局部仍会更新。采集可能漏过短暂完整态，不能把未观察到的ID全部算成客户端丢帧。源端全轮最大绘制间隔约40.2/41.0ms，没有数百毫秒的源定时停顿。

Cocoa 开始约1s内可读完整VIDEO，随后主要只剩tile3的108行可校验；tile0/1/2所需316区域均失读，静态DONE后恢复完整。自动分析保留0个已验证一致VIDEO ID、100%未知的原始计数；**这不表示0FPS，也不表示没有混帧**。

额外独立诊断轮的一张2048×1536原分辨率窗口图仍只有右侧108/432区域CRC有效，前三tile原始帧号分别997/1003/990，最后tile为1007；前三tile所有CRC均不匹配，仅1区域出现不确定亮度位。对ID900–1050的有界检查也无法把前三tile各自的CRC解释为单个邻近帧。动画停止后的静态图432/432为DONE2273。它排除了仅由1024捕获缩放或永久ROI错误引起的解释，支持动态区域/码内部不同步或失真的问题，尚不能唯一归因GPU、上传、解码或服务端。

诊断轮含额外窗口截图，明确排除正式性能统计。完整屏幕FPS对Cocoa保留null，而非强行做优劣排名。Spicy仍停留在前轮viewport预检未完成，本轮没有新增可比数据。

## 条件、开销与校验

两端使用同一Mac、同一QEMU PID218219、同一HTML/JS、4vCPU/6144MiB、virtio1920×1080、gtk gl=off、临时streaming-video=all。Cocoa为官方CocoaSpice加UTM native与官方单行TLS pending回移的最小宿主，不是完整UTM或完全未改的上游包；二进制/库来源沿用前轮，哈希已核验。

主窗口1024×768 points，整窗原图2048×1536；共同ScreenCaptureKit捕获1024×768，guest ROI[0,112,1024,576]，queueDepth3，无音频/子窗口/光标。只读标记并保存低量向量，PNG在停止后编码。请求120Hz不等于实际120Hz。Maspice视频分析窗capture间隔p50/p95/max约9.4/24.4/43.0ms，callback lag p95约1.34ms，处理p95约3.98ms；没有倒序、缺timestamp或metadata溢出。原始时钟与转换host PTS在一个tick内对齐。

采集器whole-run wait4 CPU约14.12%/14.67%单核，包含校准和落盘，是实测干扰而非零开销；两端使用同一版本。结果不可直接混入上一轮未持续捕获的CPU百分比。输入保留真实采样间隔和helper pre/post区间，忽略不可靠raw lastOld字段，独立找完整上一ID作为下界。

验证包括clang warnings-as-errors、JS标准CRC及432区域离线校验、独立JS图→native解码与损坏/混合拒绝、分析器13项合成二进制测试、真实事件/源时序/原始向量复算、原分辨率图像审核。未修改产品代码，也未冒称重跑此前757/57项产品测试。
